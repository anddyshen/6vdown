# 6vdown · 影视资源站下载与追剧自动推送器（Windows 桌面版 & 网页版 & Docker）


> 📌 **开源说明**：本源码全部由 DeepSeek 和 Gemini 自动生成，完全公开，欢迎大家随意修改、复制、二次开发与使用，无需任何授权或署名。

> **多端支持与全天候自动追剧**：
> - **Windows 桌面端**：常驻系统托盘，自动监听剪贴板与悬浮窗拖拽（磁力 / PT / http 链接）并一键推送到远程下载器；支持多站点首页区块与详情页资源快速解析、增量比对与一键打包 exe；
> - **网页版 & Docker 部署**：内置轻量 FastAPI 后端与现代化响应式 Web 控制台，支持 Docker / Docker Compose 一键部署在群晖（Synology）、威联通（QNAP）、Unraid、TrueNAS 与各类 Linux NAS/VPS 服务器上，实现 7×24 小时低功耗常驻运行；
> - **多站点聚合与跨站搜索**：内置支持 6v电影（hao6v/6v520 模板）、电影港（dygang）、电影港新版（dyg7）、BT之家 1LOU（1lou.me）等多站点资源聚合，支持全站跨站关键词检索与按需智能抓取；全协议识别磁力（Magnet）、ED2K 电驴、迅雷专用链、FTP 直链、种子附件（.torrent）及各大网盘分享链接；
> - **追剧自动订阅与 Emby 联动**：支持剧集自动巡检更新，智能根据画质优先级（1080P/4K/720P）选集防重；与 Emby 媒体库深度联动比对库内已有集数，自动下载缺失集数并可免确认直接自动推送到远程下载器（qBittorrent / Transmission / Aria2），自动附带分类标签与操作日志；
> - **安全鉴权与免密记忆**：Web 端提供登录安全保护，支持「记住密码」免除重复输入，登录会话跨服务重启持久化。

## 功能特性

### 一、基础功能

1. **剪贴板自动监听与解析**：识别磁力 `magnet:?xt=urn:btih:...`、`.torrent` 直链、
   PT 站 `download.php?passkey=...` 直链、普通 http(s) 资源直链，自动发送到当前激活主机；
   http 链接可设处理方式（询问/发送/忽略）。自动去重仅作用于剪贴板/拖拽来源，防止复制循环。
2. **下载主机管理**：支持 qBittorrent（Web API v2）、Transmission（RPC）、Aria2（JSON-RPC）；
   可新增/编辑/删除/测试连接，设置地址、端口、用户名、密码（Windows DPAPI 本地加密），
   并可随时指定某一台为**激活主机**作为默认发送目标。
3. **系统托盘**：最小化/关闭窗口常驻右下角任务栏；托盘含：显示主窗口、显示/隐藏拖拽小窗、
   开始解析、**剪贴板监听**（取消勾选即暂停自动监听，图标变灰）、**弹窗提示**（独立开关，
   仅控制右下角提醒，与“剪贴板监听”互不影响）、**下载服务器切换**（动态子菜单，直观显示已配置主机并支持一键切换激活目标）、退出。
4. **程序图标**：运行时绘制“播放+磁力”风格图标，支持彩色/灰阶切换，并可用 `tools/gen_icon.py`
   生成 .ico 供打包嵌入。
5. **右下角提醒弹窗**：渐变淡入→驻留→淡出，自动关闭（时长可设，默认 6 秒），多消息向上堆叠，
   可带操作按钮（如“打开结果页”）。是否弹窗由“弹窗提示”开关统一控制。
6. **操作痕迹历史**：每次发送自动记录任务名、链接、来源（剪贴板/拖拽/站点/手动）、目标主机、
   时间与结果；历史页支持**关键词 / 拼音首字母实时筛选**、删除、再次发送。
7. **可拖拽小窗**：独立悬浮窗，网页链接/磁力文本直接拖入即发送；默认出现在屏幕右下角，
   按住任意位置可拖动，位置自动记忆（仅当用户主动拖过），可置顶、可显隐。
8. **多主机激活记忆**：激活主机等设置保存在本地配置，重启后仍生效。

### 二、指定网站解析与自动下载

1. **首页区块解析**：解析首页更新区并归属到以下区块（可在设置中勾选启用的区块）：
   最新电影 / 经典高清 / 更新电视剧 / 国剧 / 日韩剧 / 美剧 / 动画电影；
   支持对真实标题关键词容错匹配（如“欧美剧”归入美剧）。
2. **镜像域名容灾**：内置预置镜像（hao6v.cc、6v520.net、6v520.cc 等）与地址发布页线索；
   可在设置中**随时增/删/改镜像域名、设当前解析源、一键检测全部镜像可用性**；
   “添加 / 编辑”使用统一对话框（地址、备注、启用），列表**双击该行或点“编辑”按钮**即可修改；
   检测可用性时显示**进行中进度条**并临时锁定检测按钮（单个镜像异常不影响整体、结束后自动恢复）；
   解析时按“当前 → 其它可用”自动降级，单个域名失效不再导致程序瘫痪。
3. **详情页抓取**：对每条首页记录抓取详情页，提取全部磁力链接与资源简介；
   抓取使用 GBK/gb18030 解码 + 规则集中配置 + 正则兜底；请求礼貌间隔可调。
4. **增量与缓存模型**：
   - 首次解析=全量；之后只比对新增详情链接，**已存在的电影不再重复抓详情**；
   - 每次解析会把“历史抓取失败或磁力为空（？）”的记录自动补抓一次；
   - 结果落库（SQLite），第二次解析后展示**与首次同样完整**的缓存列表，仅追加期间新增；
   - 设置中提供**“重置解析数据”**：清空解析缓存回到首次解析状态（不影响主机/镜像/历史）。
5. **结果列表**：以【名称 · 日期 · 简介+磁力数】展示；每条带勾选框、**详情**（打开分集/版本磁力框）、
   **发送**（一键发送到激活下载器）；支持表头点击升降序（星标归组、日期按真实时间、磁力按数值）。
   列表上方提供**实时筛选框**：支持中文/英文/数字关键词或**中文拼音首字母**（如 `dy`=电影、`jq`=剧情），
   仅匹配列表**可见文字**（名称 / 简介 / 磁力数），输入即过滤、清空即恢复全部。
6. **重要资源标识**：红链推荐或标题含“经典”的条目在列表中显示 ★ 星标。
7. **本次新增高亮**：增量解析后，当次新增记录自动**置顶**（内部按日期倒序，最新在最上），
   整行**金色高亮**并带“〔新〕”前缀；点**【恢复新增排序】**可随时回到该排序；
   手动点击表头排序会保留高亮标识而不强制置顶。
8. **多集剧集**：双击磁力数≥2 的条目（或点“详情”）打开分集选择框——
   按“第 X 集 / SxxExx / 第X季第X集”等自动分组；同一季排一起、季号大在前、同季最新一集在最上，
   即使命名无法识别也保证**最上一行为最新候选**；名称完整显示、悬停可见全名、磁力链接截短显示、
   **双击链接即复制**；支持逐条发送/复制/一键发送该资源全部。
9. **解析任务流**：
   - 点击“开始解析”时的行为可设默认值：**每次询问 / 默认后台执行 / 默认查看过程**；
   - 后台执行时静默运行，控制台面板实时滚动输出进度；解析完成后右下角渐变弹窗
     （含“打开结果页”按钮），提醒查看并选择发送。
10. **剧集增量**：站点更新的剧集 = 首页新增文章，会按增量自然抓取其最新集详情。

### 三、程序与体验设置

1. **界面**：单窗口多标签（解析工作台 / 历史记录 / 设置）；主题默认跟随系统亮/暗，可手动切换；
   深浅色下的高亮、按钮、弹窗配色均自适应。
2. **启动行为**：可选“启动时显示主窗口”或“启动时最小化到托盘（右下角提示已打开）”。
3. **剪贴板监听启动策略**：始终启用 / 始终禁用 / **记住上次关闭时的状态**（默认）。
4. **弹窗提示独立开关**：托盘“弹窗提示”与设置页“右下角提醒”为同一开关，与“剪贴板监听”互不影响——
   即便剪贴板监听被关闭（图标变灰），手动“发送”等操作仍会正常弹窗反馈。
5. **解析默认操作**：每次询问 / 默认后台执行 / 默认查看过程（自动进入控制台实时输出）。
6. **开机自启**：设置页开关（写入注册表 Run 键；exe 打包环境下生效）。
7. **拖拽小窗**：可显示/隐藏、可置顶、可拖动并记忆位置；默认出现于屏幕右下角，
   深色高对比样式便于文字识别。
8. **历史记录页**：完整操作痕迹，支持查询、删除、再次触发发送。
9. **下拉控件交互**：设置页下拉框采用“点击展开”选择，鼠标滚轮不会误切换选项。
10. **定时自动解析**：本期未启用，已在调度层预留接口，后续可直接挂接。
11. **拼音检索**：工作台与历史记录支持中文关键词 / 英文数字 / **中文拼音首字母**检索
    （依赖 `pypinyin`，未安装时自动降级为普通文本匹配）。
12. **托盘快捷切换下载服务器**：托盘右键菜单提供“下载服务器”动态子菜单，直观显示已配置的主机名称及激活状态，单选即刻切换当前激活发送目标并弹窗反馈，主界面设置页同步刷新。

依赖：`PySide6>=6.6,<6.7`、`requests`、`pypinyin>=0.49.0`（详见 `requirements.txt`）。

```powershell
.venv-run\Scripts\python.exe main.py      # 直接运行
.venv-run\Scripts\python.exe -m src.app   # 等价入口（VS Code 里 ▶ 运行 src\app.py 也可，会自动补包路径）
run-venv.bat                              # 一键：建 .venv-run + 装依赖 + 启动
run.bat                                   # 系统 Python：装依赖后启动（备选）
python -m unittest discover -s tests -p "test_*.py"   # 单元测试
```

```powershell
build.bat        # 输出 dist\6vdown.exe（PyInstaller --onefile --windowed，含自定义图标）
```

### Docker 容器化与 Web 服务运行（NAS / 服务器 7×24h 追剧）

本项目提供完全无头的轻量 Web 服务端（FastAPI + 原生自适应响应式 WebUI），支持在群晖 Synology、威联通 QNAP、Unraid、TrueNAS 及普通 Linux 云服务器上 7×24 小时无人值守运行，具备自动定时巡检更新、自动推送下载器、Emby 媒体库深度联动与跨站影视搜索等完整能力。

#### 1. 群晖 Synology NAS 安装与部署

##### 准备工作：创建存储目录与本地数据迁移
1. 打开群晖 **File Station（文件总管）**，在 `docker` 共享文件夹下新建子文件夹 `6vdown`。
2. 在 `6vdown` 内部再新建一个子文件夹 `data`（完整路径如：`/docker/6vdown/data`），用于持久化保存数据库、配置与日志。
> **💡 本地数据无缝迁移**：若想直接使用 Windows 桌面端已有的追剧订阅、历史分集和配置，只需将本地 `data/` 目录下的 `6vdown.db` 和 `config.json` 复制上传到群晖的 `data` 文件夹中即可，程序启动后自动无缝读取。

##### 方式一：Container Manager「项目」一键部署（推荐，DSM 7.2+）
1. 打开群晖 **Container Manager** 套件，点击左侧 **「项目」** ➔ **「创建」**。
2. 填写基本信息：
   - **项目名称**：`6vdown`
   - **路径**：选择刚刚建好的文件夹 `/docker/6vdown`
   - **来源**：选择 **「创建 docker-compose.yaml」**
3. 将以下配置粘贴到文本框中：
```yaml
version: '3.8'

services:
  6vdown:
    image: ghcr.io/anddyshen/6vdown:latest
    container_name: 6vdown
    restart: unless-stopped
    # 采用 host 主机网络：容器与群晖处于完全相同的家庭网段，源 IP 即为 NAS 本机 IP
    # 彻底解决 Transmission/qB 局域网白名单拦截、免密失效与跨网段路由问题
    network_mode: host
    volumes:
      - ./data:/app/data
    environment:
      - TZ=Asia/Shanghai
      - C2DOWN_DATA_DIR=/app/data
      # 监听端口（Host 模式下直接占用宿主机端口，默认 5080 避开常见 8080 冲突）
      - PORT=5080
```
4. 点击 **「下一步」** ➔ **「完成」**，群晖将自动拉取镜像并完成启动。浏览器访问 `http://<群晖IP>:5080` 即可。

##### 方式二：Docker 图形化向导手动部署（DSM 6.x / 7.1）
1. 打开 **Container Manager / Docker** 套件 ➔ 进入 **「注册表」** 搜索并下载 `ghcr.io/anddyshen/6vdown:latest`。
2. 下载完成后，在 **「映像」** 中选中它，点击 **「运行」**：
   - **网络设置**：网络模式选择 **「使用与 Docker Host 相同的网络 (host)」**（推荐，与家庭同一网段）；
   - **容器名称**：`6vdown`，勾选 **「启用自动重新启动」**；
   - **存储空间设置**：点击“添加文件夹”，选择群晖上的 `docker/6vdown/data`，装载路径填 `/app/data`；
   - **环境**：新增环境变量 `TZ` = `Asia/Shanghai`，`PORT` = `5080`。
3. 点击 **「下一步」** ➔ **「完成」** 启动容器。

##### 方式三：SSH 终端命令行部署
登录群晖 SSH 终端，进入目标目录执行：
```bash
docker run -d \
  --name 6vdown \
  --restart unless-stopped \
  --net=host \
  -v /volume1/docker/6vdown/data:/app/data \
  -e TZ=Asia/Shanghai \
  -e PORT=5080 \
  ghcr.io/anddyshen/6vdown:latest
```

#### 2. 通用 Linux / 云服务器部署

##### 使用 Docker Compose 部署：
在任意目录创建 `docker-compose.yml`：
```yaml
version: '3.8'
services:
  6vdown:
    image: ghcr.io/anddyshen/6vdown:latest
    container_name: 6vdown
    restart: unless-stopped
    ports:
      - "8080:8080"
    volumes:
      - ./data:/app/data
    environment:
      - TZ=Asia/Shanghai
```
执行 `docker compose up -d` 即可启动。

##### 本地 Python 源码直接运行 Web 服务（免 Docker）：
```bash
pip install -r requirements-server.txt
python server.py --host 0.0.0.0 --port 8080
```

#### 3. 访问与配置注意事项

- **控制台访问**：启动成功后，浏览器打开 `http://<NAS局域网IP>:5080`（或相应端口）即可进入 Web 控制台。
- **局域网下载器与 Emby 地址**：在 Docker 容器内部访问其他服务时，请避免使用 `localhost` 或 `127.0.0.1`，请直接填写宿主机/局域网实际 IP（如 `http://192.168.1.x:8080` 或 `http://192.168.1.x:8096`）。
- **镜像权限说明**：若群晖拉取 `ghcr.io/anddyshen/6vdown:latest` 提示认证失败或未找到，可在 GitHub 仓库页面右侧进入 **Packages** ➔ **6vdown** ➔ **Package settings** 底部将可见性设为 **Public**（公开）。

### 绿色便携（绝对绿色）
- 将 `6vdown.exe` 放入任意文件夹双击运行，exe 同级自动生成 `data\`（数据库 / 配置 / 缓存 / 日志 / 单实例锁）；
- 把整个文件夹拷贝到其它电脑或目录即可直接使用，**数据随目录走**；
- **不写任何系统目录**（不写 `%APPDATA%`、不写注册表）；若程序目录只读（如 U 盘写保护，
  或放在 Program Files），回退到“当前工作目录”的 `data\`，同样不落系统盘用户目录；
- 首次启动会把旧版留在 `%APPDATA%\C2Down`、`%APPDATA%\6vdown` 的数据库/配置/缓存**单向迁移**到
  程序目录（只读旧目录，此后只读写程序目录），旧文件 `data\c2down.db` 也会自动改名为 `6vdown.db`。

```
│ SQLite（6vdown.db） · config.json · cache/ · 日志          │
└──────────────────────────────────────────────────────────────┘

```

## 常见问题（FAQ）

1. **第二次解析后列表没有“新增”/和上次一样？** 这是缓存+增量模型的设计：无新增时展示既有缓存
   并提示“无新增”；有新条目时自动置顶并金色高亮（〔新〕）。
2. **磁力数列显示“？”**：该条详情此前抓取失败或没有抓到磁力，下一次解析会自动补抓；
   也可在设置中“重置解析数据”后全量重建。
3. **托盘图标变灰后点“发送”还有弹窗？** 已拆分为两个开关：图标变灰仅表示“剪贴板监听”暂停；
   弹窗提示由“弹窗提示”独立控制。
4. **没有任何右下角弹窗？** 检查托盘“弹窗提示”或设置页“右下角提醒”总开关是否被关闭。
5. **数据存在哪里？** 绝对绿色：只放 exe 同级的 `data\`（源码运行为项目 `data\`）；
   程序目录只读时回退到当前工作目录的 `data\`，**不会写 `%APPDATA%` 等系统目录**。
   设置页提供“打开数据目录”按钮直达。
6. **启动报 Qt DLL 加载失败？** 多为 Anaconda + 新版 PySide6 兼容问题：请用 `.venv-run` 并按
   `requirements.txt` 安装 PySide6 6.6.x（见“运行与打包”）。
7. **双击某行没反应？** 该行磁力数 <2 时不弹分集框（可用“详情”按钮查看）。
8. **解析页输入拼音字母不生效？** 请输中文名称的连续首字母（如 `dy`=电影、`mg`=美剧），仅匹配列表可见文字；并确认运行环境已安装 `pypinyin>=0.49.0`（未安装时仅支持普通文字搜索）。

## 风险与限制

1. 站点域名可能再次失效：依靠镜像管理、一键检测与发布页自动发现缓解，无法保证永久可用；
2. 站点改版可能改变页面结构：解析规则集中管理、便于快速修复，解析失败会给出明确提示；
3. PT 站需登录的链接不在支持范围：仅支持带 passkey 的直链，登录页依赖用户提供 Cookie；
4. 未来若站点出现验证码 / WAF 等防护，自动化解析将不可用（程序会给出降级提示）；
5. PySide6 单文件 exe 体积约 50–90MB，onefile 首次启动需要数秒解压，属正常。

## 待办与规划

- 定时自动解析（接口已预留，后续在设置中启用）；
- 解析规则的外部化/热更新与站点改版自检；
- 更多镜像自动发现数据源；
- 多标签结果对比与导出。
